华为p9刷机教程

candy2026-11-072026-11-07

华为 P9 (EVA-AL00) 刷 LineageOS 16 microG 完整教程（fastboot + 原厂 recovery 路线）

本教程由一次真实刷写过程整理，已在 EVA-AL00（EMUI 8.0.0.550 C00）上实测走通。
核心结论：EMUI 8 上没有可用的 TWRP，正确路线是「fastboot 刷 system + 原厂 recovery 恢复出厂」，全程不依赖第三方 recovery。
本文取代早期 FLASH-PLAN.md 中基于 TWRP 的方案（那条路在本机已验证失败，原因见第 3 节）。

1. 设备与目标

项 值
机型 HUAWEI P9 EVA-AL00（SN PBV7N16C29017300）
SoC 海思麒麟 955 / hi3650
架构 / 分区 arm64-v8a，A-only（无 slot 后缀），Treble 已启用
底固件 EMUI 8.0.0 B550(C00)，安全补丁 2020-07-01
Bootloader 已解锁（fastboot oem get-bootinfo 返回 unlocked）
目标 ROM lin16-microG treble_arm64_a_lineage16（LineageOS 16 / Android 9，microG 非真 GMS，2025-12 EOL）

只替换 system 一个分区：GSI 复用 EMUI 8 的 treble vendor 和原厂内核驱动硬件，vendor / kernel / modem 全部保持不动。

2. 物料与校验

工作目录 ~/p9-lineage/，共 4 个文件：

文件 大小(字节) 类型 MD5

treble_arm64_a_lineage16_20251223_system.img（解压产物） 1,938,542,872 Android sparse 镜像 v1.0 —

3. 为什么不能用 TWRP（踩坑记录，先读）

EMUI 8 采用拆分式 boot 布局：内核在独立分区 kernel(p30)，recovery 只放 ramdisk（recovery_ramdisk p32，且镜像头 kernel_size=0）。

而 OpenKirin TWRP 3.1.1-1 是 2017 年为 EMUI 5（b380 Nougat 内核）时代的统一 recovery 分区打的完整 boot 镜像，自带内核。对比两个 ANDROID! 头：

字段 TWRP 3.1.1-1 原厂 B550 recovery_ramdisk
kernel_size 10,825,602（自带内核） 0（无内核）
ramdisk 地址 0x08000000 0x11000000

把自带内核的完整 boot 镜像塞进期望「纯 ramdisk」的分区，fastboot 层虽显示 Writing OKAY，但引导栈解析失败 → 开机进 recovery 时出现白底 + Android 机器人 + “error type”，几秒后自动回退主系统。

旁证（官方/作者口径一致）：

  • ROM 作者 MSe1969 原帖：“Can I flash this rom via TWRP? **No. TWRP can’t decrypt the /data partition. You need the original Huawei recovery and fastboot is the only option.**”
  • OpenKirin：EMUI 8.0 须配 stock recovery/ramdisk，不支持 TWRP 等第三方 recovery。
  • 有 EVA-AL00 用户报告同款现象：EMUI 8 下刷该 TWRP 得到 “broken recovery with Error 11 and 2”。

结论：不要刷 TWRP。 若已误刷导致 error 页，用第 5 节步骤刷回原厂 recovery 即可修复，主系统不受影响。

4. 关键分区表（实测 by-name 映射）

分区 块设备 处理
system mmcblk0p54（≈1912 MiB） 刷 treble 镜像
vendor mmcblk0p57（≈544 MiB） 保持不动
userdata mmcblk0p60（f2fs，加密走 dm-0） 原厂 recovery 恢复出厂清空
cache mmcblk0p44 原厂 recovery 清 cache
kernel mmcblk0p30 不动
ramdisk mmcblk0p31 不动
recovery_ramdisk mmcblk0p32（32 MiB） 刷原厂镜像修复/基线
erecovery_*(p22-24/37)、modemnvm(p12)、bootloader、modem — 一律不碰（防 ARB/硬砖）

fastboot 分区名用海思命名：system、recovery_ramdisk。没有叫 recovery 的分区——对它 flash 会报
FAILED (remote: 'partition length get error')，此错误在 Writing 前失败，不写入任何内容。

5. 执行步骤

阶段 0 — 进 fastboot 并确认解锁

海思 fastboot 限制：fastboot getvar all、fastboot boot 会被拒（Command not allowed），属正常；
fastboot oem get-bootinfo 可用。Mac 端 standard fastboot 能 flash 已知分区名。

阶段 1 — 修复/确保原厂 recovery（写分区，需确认目标）

  • 仅写 **recovery_ramdisk (p32)**。期望输出 Writing 'recovery_ramdisk' OKAY。
  • skip copying ... avb footer (partition size: 0) 警告是海思上报分区大小为 0 的无害提示，镜像 33,554,432 字节正好等于分区大小。
  • 作用：把 recovery 恢复成格式正确的原厂镜像（若之前误刷 TWRP，此步修好白底 error 页），并为阶段 3 的恢复出厂做准备。

阶段 2 — fastboot 刷 system（核心写入）

先跑第 2 节的 sparse 校验，确认 FIT OK，然后：

  • 仅写 **system (p54)**，vendor/kernel/modem 不碰。
  • fastboot 识别 sparse 魔数后自动分片下发（本机分 5 片 Sending sparse 'system' 1/5 … 5/5，每片 Writing OKAY，总耗时约 70 秒）。无需 fastboot erase system，flash 整体覆盖文件系统。
  • 期间不要拔线。看到 Finished. 即成功。

阶段 3 — 原厂 recovery 恢复出厂（清 /data，物理按键）

本机实测 fastboot reboot recovery 与 adb reboot recovery 都会被海思忽略、直接正常开机，所以必须物理按键。
且要拔 USB 线，否则音量上+电源可能进联网的 eRecovery（白底“下载最新版本并恢复”），而不是标准 recovery 菜单。

  1. 长按电源约 10 秒强制关机，屏幕全黑后松手。
  2. 拔掉 USB 线。
  3. 按住 音量上 + 电源：出现 Huawei Logo/震动后，松开电源、音量上继续按住，直到出现 recovery 菜单。
  4. 标准 EMUI recovery 菜单为三项：重启设备 / 恢复出厂 / 清除 cache 分区（看到这个就对了；若是 eRecovery 白屏则不要点，重来）。
  5. 依次点：
    • 恢复出厂 → 确认（格式化 /data，清除旧加密元数据）；
    • 清除 cache 分区；
    • 重启设备。

阶段 4 — 首次开机与验证

  • 首次开机做 dex 优化，可能卡 Logo/黑屏 3–10 分钟，插电等待，勿强制重启。
  • 正常会进入 LineageOS 设置向导（语言、Wi-Fi…）。
  • 插回 USB，若弹「允许 USB 调试」勾选一律允许并确定，然后：

逐项手测硬件：双卡信号/基带、Wi-Fi、蓝牙、相机（已知 1080p 后置录像可能异常）、通话、音频、GPS、指纹。

6. 现象解释 / 排错

现象 原因与处理
开机弹「To start Android, enter your password / 启动 Android 请输入密码」 还没恢复出厂，/data 仍是旧 EMUI 加密数据，新系统解不开。不用知道密码，按阶段 3 恢复出厂即可消除。
白底 + Android 机器人 + “error type”，几秒后回主系统 TWRP 镜像结构与 EMUI8 拆分区不匹配，recovery 启动失败回退。按阶段 1 刷回原厂 recovery_ramdisk 修复。
FAILED (remote: 'partition length get error') 分区名错误（如对 recovery flash）。本机用 recovery_ramdisk、system。失败在写入前，未改任何分区。
fastboot reboot recovery / adb reboot recovery 无效、直接进系统 海思忽略软件 recovery 引导，改用物理按键（拔线 + 音量上+电源）。
adb 报 device unauthorized 设备已正常开机进 Android，但未授权调试。在手机屏幕点「允许 USB 调试」。原厂 recovery 菜单下 adbd 不启动，属正常。
skip copying ... avb footer ... partition size: 0 海思 fastboot 上报分区大小为 0 的无害警告，不影响写入。
Command not allowed（getvar/boot） 海思私有 fastboot 门禁用这些命令，不影响 flash/oem get-bootinfo。

7. 风险与回退

风险

  • ARB 反回滚熔丝：本流程只刷同版本 B550 配套镜像与同代 treble ROM，不降级 bootloader/modem 以规避触发；ARB 计数无 root 不可读，不存在零风险。
  • 阶段 3 恢复出厂会清空 /data（动手前确认已备份）。
  • FRP：刷前确认 设置→账号/华为账号 列表为空，避免恢复出厂后要求账号验证。
  • microG 不是 Google Play 服务：依赖 SafetyNet/Play Integrity 的银行 App、部分游戏可能不可用。
  • 天花板：Android 9，安全补丁冻结 2022-01，ROM 已于 2025-12 EOL。

回退方案

  • R1 回 fastboot 刷回原厂 recovery（boot 的内核本就没动）：
  • R2 system 被 treble 镜像覆盖后若要恢复原厂开机，需重刷完整 EMUI B550 固件（eRecovery 三键或 dload，另备官方固件包）。
  • R3 任何阶段勿刷 bootloader/modem/modemnvm，勿降级，防 ARB 硬砖。

8. 执行原则

  • 每个写分区动作执行前，先列明确切命令与目标分区，确认后再发。
  • Mac 端只自动化 adb/fastboot；阶段 3 的 recovery 触屏动作为物理操作。
  • 一次只推进一个写入步骤，看到 OKAY/Finished. 再进下一步。
